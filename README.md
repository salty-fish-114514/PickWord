# PickWord

> **写作不一定要从空白处猜下一个词。**
>
> 以「选择题」而不是「填空题」的方式写作：你写下正文，本地模型在光标处提供下一个 token 的候选；选哪个、改不改、什么时候继续写，始终由你决定。

PickWord 是一款面向写作者的 Windows 本地写作软件。它不是“一键生成小说”的工具，也不试图替你写完整段落。它更像一支随时递上备选词句的笔：在需要一点灵感的时候出现，在你不需要的时候退到一旁。

**当前版本是功能 Demo，正在进行安装体验与硬件兼容性测试。**


## 下载安装

**Windows 10 / Windows 11，x64。**

请前往本仓库的 **Releases** 页面下载 Windows 安装程序。

安装包只包含 PickWord 主程序，**不包含模型权重或 llama.cpp 后端**。首次启动会进入独立的设置向导，帮助你检测硬件，并下载或选择已有的引擎与模型。所需磁盘空间、内存及显存取决于你选择的模型和运行方式。

> 当前安装包未进行代码签名，Windows 可能显示来源或信誉提示。请先确认文件来自你信任的发布页面；不要仅因 README 的说明就无条件绕过系统警告。

### 首次启动

1. 安装并打开 PickWord。
2. 在设置向导中检测 CPU、内存、GPU 和可识别的显存信息。
3. 确认推荐的运行引擎，也可以自行改选。
4. 选择预设模型，或指定本地已有的 `.gguf` 文件。
5. 选择引擎与模型的存放位置，开始部署。
6. 部署完成后进入文库，等待本地模型加载完毕即可写作。

已有可用环境的用户，可以在向导的高级选项中直接指定本地 `llama-server.exe` 和 `.gguf`，不必重复下载。例如，引擎路径可以是：

```text
D:/llama-b8868-bin-win-hip-radeon-x64/llama-server.exe
```


## PickWord 如何帮助你写作？

### 下一个 token，由你来选

写作时，PickWord 请求本地模型预测光标后的下一个 token，并把多个候选展示在光标附近。你可以用键盘或鼠标选择，也可以完全忽略候选，继续自己写。

### 正文、风格和大纲各司其职

- **正文**是作者正在写的内容，不是等待 AI 接管的空白。
- **风格参考**可选：希望模型更贴近某种表达方式时再开启。
- **大纲**可选：需要限定当前章节方向时再开启。
- **大纲锚点**可选：可以指定当前章节在正文中的起点。

没有风格或大纲，也可以直接写。PickWord 不要求先填完一套表单，才能开始创作。

当前预测主要使用**光标之前**的正文，不会把光标之后的文字当作双向填空材料。

### 为连续写作设计的交互

- 光标附近显示候选，不必在编辑器和聊天窗口之间来回切换。
- 支持键盘选择、翻页与概率随机取词。
- 支持普通刷新与更积极的快速模式。
- 输入法组字期间暂停候选交互，避免抢走中文输入法的按键。
- 支持查找替换、撤销重做、字数统计和明暗主题。
- 模型出现一定的结束倾向时，可以给出不打断写作的弱提醒；这**不意味着模型真的理解了故事何时结束**，请你优先相信自己的判断。


## 文库与文件

PickWord 提供文库首页，可以创建、打开、重命名和管理多篇文稿。每篇文稿独立保存，不需要把整本书挤在同一个编辑框里。

当前可从 `.txt`、`.md` 和 `.docx` 导入内容；Word 文档以**纯文本**方式读取，不保留原文档的复杂排版，也不会写回原 Word 文件。正文可以导出为 TXT 副本。

风格、大纲、锚点等写作信息与正文分开保存。**导出 TXT 是获得一份副本，不是将当前文稿切换到那个导出位置。**

> 写作软件首先要保护稿件。虽然项目已经实现日常保存流程，这仍是测试版本；重要文稿请自行保留备份，尤其是在迁移文库、测试新版本或尝试异常退出场景时。

## 本地运行与隐私

写作时，候选请求发送给本机启动的 `llama-server`，而不是要求你登录一个在线写作服务。首次部署引擎和模型则需要访问相应下载源；选择本地已有文件时，可以避免重复下载。

## 运行引擎与硬件适配

PickWord 使用独立的 `llama-server` 进程提供本地推理能力。向导会尝试根据检测到的硬件推荐 CPU、NVIDIA CUDA、AMD HIP/ROCm 或 Vulkan 等运行方式，并允许手动选择。

**推荐值不是兼容性保证。** GPU 驱动、后端构建、模型量化、上下文长度以及 GPU 卸载层数，都会影响能否成功加载模型。尤其是“大模型 + 较长上下文”，即使向导能够完成下载，也不代表一定不会内存不足。

如果模型加载失败，可以依次尝试：

1. 查看软件中的后端状态和日志。
2. 换用更小的模型或更低的量化档位。
3. 调低上下文长度或 GPU 卸载层数。
4. 更换运行引擎，例如尝试 Vulkan 或 CPU。
5. 确认本机驱动与所选预编译后端兼容。

### 使用自己的模型与引擎

高级用户可以指定已有的 `llama-server.exe` 和 `.gguf` 文件。请尽量使用你信任的下载来源，并确保所选后端能够识别模型格式。PickWord 不会替第三方模型或预编译程序保证兼容性。

## 当前版本的边界

这是用于分发测试的 Demo，而不是已经覆盖所有设备的正式发行版。当前尤其需要验证：

- Windows 10 / 11 上不同 CPU、显卡和驱动组合的运行情况；
- 核显、独显并存时的硬件识别和显存显示；
- 大模型在不同 RAM / VRAM 条件下的加载表现；
- 保存、异常退出和日志隐私等边界情况。

项目目前也**没有自动更新功能**。获得新版时，请查看发布页面及其说明。

## 项目结构

```text
src/
├── main/                 Electron 主进程：窗口、文库、后端、部署
├── preload/              受限的 renderer ↔ 主进程接口
├── renderer/src/
│   ├── Bootstrap.tsx     首次设置与现有应用之间的启动门控
│   ├── App.tsx           文库首页与单篇写作界面
│   └── components/       候选浮窗、设置向导等界面组件
└── shared/               主进程和界面之间的数据类型

resources/
└── backend.json          仅供本机开发使用；请勿提交个人路径
```

技术栈：Electron、electron-vite、React、TypeScript、原生 CSS，以及作为独立子进程运行的 llama.cpp。

## 反馈与协作

如果你愿意帮助测试，欢迎反馈：

- Windows 版本；
- CPU、RAM、GPU 型号及显存；
- 选择的运行引擎、模型和量化版本；
- 出现问题的操作步骤；
- **脱敏后**的错误信息或日志。

请不要公开上传真实文稿、完整提示词、个人文件路径或未经检查的后端日志。兼容性测试最有价值的反馈，不只是“能不能启动”，还包括加载耗时、写作时的响应速度，以及哪里让非技术用户感到困惑。
